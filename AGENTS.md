# User communication preferences

Explicit user preference, September 14, 2026; apply throughout this project.

- Reports and implementation explanations must be visual first: use a simple flowchart, diagram or visual status map whenever the user asks for a report.
- Avoid walls of text. Keep accompanying prose very short and show one understandable chunk at a time.
- Teach the real technical terms (frontend, backend, API, database, deployment, etc.) rather than avoiding them. Whenever introducing a term, put a short everyday-language meaning beside it and show its concrete role in this app. The user wants to learn the vocabulary without unexplained jargon or syntax-heavy detail.
- The user wants to understand what the app does, how its parts connect, what is finished and the next step; syntax-level detail is usually unnecessary.
- Do not overwhelm the user with a full implementation checklist in chat. Keep detailed evidence in linked files and show only the relevant visual summary.
- During implementation, explain the next small milestone and demonstrate its result so the user's understanding keeps pace with changes.
